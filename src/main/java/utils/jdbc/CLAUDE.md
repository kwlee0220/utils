# utils.jdbc

JDBC connection/query helpers. User-facing guide (Korean): [README.md](README.md) — builder entry points, URL formats, pooling, resource ownership, exception policy, the type table. The package was reshaped by a review completed on 2026-11-03 (the tracking doc `docs/reviews/jdbc-review.md` has been deleted; this file and the README record the outcomes). A follow-up review on 2026-11-03 fixed secret leaks in error messages, early-closed `ResultSet` connection leaks, schema-name case, jar paths with spaces, trailing comments in `countQueryRows` and sub-second `toPostgresInterval`, and added `query`/`queryFirst` binder overloads and `LOCAL_DATE`. Change-history notes were then removed from Javadoc/comments — don't add "이전에는…" sentences back; record changes here instead.

Downstream callers are all in mdt-instance (`mdt.persistence.timeseries` — `JdbcRecordsReader`, `JdbcTail/Range/FullRange*Segment`; `mdt.persistence.asset.jdbc`; `mdt.ksx9101.jpa.JpaPersistenceUnitInfo` uses `JdbcConfiguration` getters). After an API change run `gradle :test --rerun -x :utils:test` in mdt-instance. Externally used surface is small: `JdbcProcessor.builder(..)`/`builder(JdbcConfiguration)`/`connect`/`executeQuery(sql)`/`countRows`, `JdbcConfiguration.parse` + getters, `JdbcUtils.fstream`/`toColumnObjectList`/`maskPassword`, `SQLDataTypes.fromSqlType(..).getJavaClass()`. Everything else has no outside caller but is kept deliberately (review #16 was rejected — don't delete `DriverDelegate`, `GeometryFormat`, `JdbcParameters`, the unused `JdbcUtils` helpers or `JdbcProcessor` methods without asking).

## Structure

- **`JdbcProcessor`** — immutable after `build()`: every config field (`m_jarFile`, `m_cloader`, `m_poolKey`, `m_maxPoolSize`, …) is `final` and set in the private constructor (before 2026-11-03 the builder assigned them after construction — unsafe publication). Mutable state: `m_driver` (guarded by `synchronized loadDriver()`), `m_pool` (`volatile`). Driver loading: explicit `classLoader` > `jarFile` (one shared `URLClassLoader` per canonical jar path — `jarLoaderKey`, also used by `PoolKey` — in static `s_jarLoaders`, never closed; the URL comes from `File.toURI().toURL()` so spaces/`#`/`%` work) > `Class.forName` + `DriverManager`. A driver loaded through a ClassLoader is instantiated once and called directly (`Driver.connect`, `null` result → `SQLException`). `connectDirect()` (package-private) is also what the pool's `DirectConnectDataSource` calls.
- **`JdbcConnectionPools`** — static `Map<PoolKey,HikariDataSource>` under `synchronized (s_pools)`. `PoolKey` = url/user/password/driver class/ClassLoader identity/jar path, null-safe. `getOrCreate` registers the shutdown hook **before** creating the pool and turns a shutdown-in-progress `IllegalStateException` into `SQLException`. `close(JdbcProcessor)` removes one pool (takes the processor so `PoolKey` stays package-private); `closeAll()` all. `JdbcProcessor.connect()` retries once if `getConnection()` failed on a pool that is closed by then (concurrent close). Hikari config: `minimumIdle=0`, idle 60 s, connection timeout 5 s, `initializationFailTimeout=-1`.
- **`JdbcConfiguration`** — mutable bean. Only `jdbcUrl` is required (`setJdbcUrl(null)` → IAE); driver/user/password are `@Nullable`. `parse(fullUrl)` is the **only** parser of `<url>?user=..&password=..&maxPoolSize=..`: extracts those three keys (`%XX`-decoded via `URLDecoder` after `+`→`%2B`, so `+` stays literal) and keeps every other parameter in the URL verbatim. Renamed from `parseString` and `JdbcProcessor.builderFromFullJdbcUrl` removed (2026-11-03, no aliases) — use `builder(JdbcConfiguration.parse(s))`.
- **`ResultSetObjectFStream<T>`** (package-private, extends `FStreams.AbstractFStream`) — the single result-set iteration implementation, returned by `JdbcUtils.fstream` and used by `JdbcProcessor.query`. Lazy (first `rs.next()` on first `next()`), remembers exhaustion (never calls `rs.next()` after `false`), emits `null` deserializer results as elements, wraps `SQLException` in `JdbcException`, closes only the `ResultSet`. Replaced `JdbcObjectIterator`/`ResultSetFStream`/`ResultSetSpliterator` (deleted 2026-11-03).
- **`JdbcUtils.bindToConnection`** — JDK dynamic proxy implementing only `ResultSet`; `close()` closes rs → statement → connection once. The statement/connection are captured when the proxy is created, never looked up at close time (a closed `ResultSet` can't answer `getStatement()`): `bindToConnection(rs, stmt, conn)` takes them explicitly (both `executeQuery` overloads use it); `bindToConnection(rs)` looks them up eagerly and throws `SQLException` if it can't.
- **`SQLDataType<T>` / `SQLDataTypes`** — interface is `getJavaClass`/`read(rs, index)`/`write(pstmt, index, value)` only (was `SQLDataType<T,S>` with three method pairs until 2026-11-03). Implementations are one private `Handler<T>` (name, Java class, SQL type for `setNull`, reader, writer lambdas); `toString()` is the type name used by `findByName`. Constants: `BOOLEAN STRING SHORT INTEGER LONG FLOAT DOUBLE DECIMAL INSTANT INSTANT_TZ DATE LOCAL_DATE TIME DURATION BINARY`. `fromSqlType(Types.DATE)` stays `DATE` (`java.util.Date`) for compatibility; `LOCAL_DATE` is reached via `findByClass`/`findByName`. Lookups: `findByName`/`findByClass` → `FOption` (were `fromTypeName`/`fromClass` → `null`), `fromSqlType(int)` → IAE naming the `JDBCType` for unsupported codes.

## Contracts worth keeping

- **Exception policy (review #5).** Public `JdbcProcessor` methods throw `SQLException` for every JDBC failure, pooled or not. `JdbcException` only where a checked exception can't be thrown (stream iteration); `queryFirst` unwraps it back to the cause `SQLException`. Callback runtime exceptions propagate unwrapped. Don't reintroduce `IOException`/`ExecutionException`/boolean-failure returns.
- **Close on every failure path.** Methods that open resources catch `Throwable`, close what they opened, rethrow (`executeQuery`, both `query` overloads); the rest use try-with-resources. Regression tests run with `pooled(1)` (`failuresAndEarlyCloseDoNotLeakPooledConnection`) and count H2 sessions (`directProcessorLeavesNoOpenSession`) — a leak shows up as a 5 s pool timeout or a session-count mismatch.
- **Resource ownership.** `executeQuery*` ResultSet owns statement + connection; `query` stream owns all three (`onClose`); `JdbcUtils.fstream` owns only the ResultSet (mdt-instance callers manage connection/statement with try-with-resources — don't make it close more).
- **Null ⇄ SQL NULL** in every `SQLDataType` (`setNull`; `wasNull()` for primitives).
- **Time zones.** `INSTANT` uses a fresh UTC `Calendar` per call (drivers may mutate it) with `get/setTimestamp` → `TIMESTAMP WITHOUT TIME ZONE` holds UTC wall-clock time. `INSTANT_TZ` uses `OffsetDateTime` via `get/setObject`. They are separate because no single write path is right for both column kinds across drivers (H2 re-interprets a Calendar timestamp in the session zone for `TIMESTAMPTZ`; `OffsetDateTime` into a zone-less column becomes session-local). `TIME` is `LocalTime` via `get/setObject`. Data written before 2026-11-03 by the old `DATE_TIME` (JVM-local) reads shifted.
- **Identifiers.** `countRows`/`dropTable` validate with `SQL_IDENTIFIER` (Unicode letters/digits/`_`/`$`, or `"quoted"` without inner quotes, optional `schema.`). `countQueryRows` strips trailing `;`/whitespace and wraps as `FROM (…\n) subquery` (no `AS` — Oracle; the newline keeps a trailing `--` comment from swallowing the `)`; `; -- c` is documented as unsupported). Metadata lookups (`tableExists`, `getColumns`) escape `_`/`%` with `getSearchStringEscape()`, default to the connection's current schema/catalog, try the name as given then in the stored identifier case (`storesUpper/LowerCaseIdentifiers`) — for an explicit schema too (schema candidates × table candidates, first hit wins); `tableExists` matches `TABLE` and `VIEW`.
- **Secrets.** `getPassword()` is package-private. `toString()` of `JdbcProcessor`/`JdbcConfiguration`/`PoolKey` print `Type[url=<masked>, user=…]` and never the password; connection errors use `JdbcUtils.maskPassword` on both the URL and the appended driver message (the cause's own message can't be changed). Argument errors never echo a locator (it contains the password — report the token count) and mask a rejected URL. Keep it that way in new messages and logs; `JdbcPasswordInMessagesTest` covers it.

Removed: `builderFromFullJdbcUrl`, `JdbcConsumer` (use `CheckedConsumerX<PreparedStatement,SQLException>`; `executeUpdate(sql, binder)` now runs the update itself and returns the count), `JdbcRowSource` and the `crud` package (2026-11-02), `FullJdbcUrlParser` (2026-11-02).

## Tests

H2 2.3.232 in-memory (`testImplementation`). `JdbcProcessorH2Test`, `JdbcProcessorMetadataH2Test`, `SQLDataTypesH2Test` use real H2; `JdbcProcessorExecuteQueryTest`, `JdbcUtilsBindToConnectionTest` use Mockito for per-resource close checks. Gotchas: use `;DB_CLOSE_DELAY=-1` and a UUID per test DB; H2 only lets admin users apply URL settings like `DB_CLOSE_DELAY` (create test users with `admin`); a jar-loaded H2 driver may still be served by the parent loader because H2 is on the test classpath (`URLClassLoader` is parent-first) — assert loader sharing, not the connection's class loader.
