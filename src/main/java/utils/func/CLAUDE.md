# utils.func

Functional building blocks used by almost every other package. User guide (Korean): [README.md](README.md) — type selection, `FOption`/`Nullables`, `Try`/`Result`, lazy values, checked lambdas, naming and exception rules.

## Contracts worth keeping

- **Exception rule.** `Exception`s are captured (`Try.of/run/accept/map/flatMap`, `Result.map/filter/flatMap`, `Checked*.try*`, `Unchecked*` wrappers' failure handlers); `Error`s always propagate and are never passed to a `FailureHandler`. `Checked*X` (where `X` may be any `Throwable`) catch `Throwable` and rethrow `Error`. Checked causes are wrapped once, as plain `RuntimeException` (`Throwables.toRuntimeException`) — `Unchecked.*OrRTE`, `Try.getUnchecked`, `Result.getUnchecked` (no `ExecutionException` layer).
- **Null rule.** `FOption.of(null)` is a *present* `null`; only `empty()` is absent. `Nullables` treats `null` as absent. `Lazy`/`UnsafeLazy` reject a `null` supplier result (`IllegalStateException`); `TimedLazy` caches `null` and `peek()` returns `FOption.of(null)` for it. `Result.failure(null)` is allowed (`EventDrivenExecution.notifyFailed(null)` produces it); `Try.failure(null)` is rejected.
- **Argument validation.** Arguments that are always used (consumer of `ifPresent`/`accept`, the mapper of `map`) are checked always; fallback arguments (supplier of `getOrElse`/`orGet`, action of `ifAbsent`/`runIfNull`) only when used. Always `utils.Preconditions` (→ `IllegalArgumentException`).
- **Value semantics.** `FOption`, `Result`, `Either`, `Try` define `equals`/`hashCode` (`Success` by value, `Failure` by cause — exceptions don't override `equals`, so effectively the same exception object). `utils.stream.MappingResult` still has none.
- **Naming.** `getOrThrow(Supplier<X>)` throws the supplied exception; an `…OrThrow` suffix means "takes a `Checked*X` lambda" (`mapOrThrow`, `ifPresentOrThrow`, `getOrElseThrow`, `acceptOrThrow`). `Nullables` uses `…OrElse` (value) / `…OrGet` (supplier): `orElse`/`orGet`, `mapOrElse`/`mapOrGet`. Overloads that differ only by `T` vs `Supplier`/`Runnable` vs `Consumer` must be avoided for method-reference callers — that is why `Nullables.run` is not an `accept` overload. `getOrElse(T)`/`getOrElse(Supplier)` overloads on `FOption`/`Try`/`Result` were kept deliberately (`getOrElse(null)` is ambiguous; use `getOrNull()`). Other current names worth knowing: `Result.cancelled`/`isCancelled`/`ifCancelled`, `Result.getOrThrow`/`toTry`; `Either<L,R>.left()`/`right()` return `FOption`; `Lazy.ofValue`/`invalidate`, `Lazy.set` returns `void`; `TimedLazy.peekOrNull`; `MultipleCases.of/when/then`; `FailureCase.getCause`.
- **`Lazy.wrap`** is a JDK dynamic proxy (interfaces only, proxy class cached). Non-public interfaces of other packages need `Method.trySetAccessible()` at invoke time; `wrap` checks it up front and throws `IllegalArgumentException` if it can't (tested from `utils.funcwrap`, a different package — same-package tests don't catch it). Object methods do not trigger the supplier (`equals` = proxy identity). Don't go back to ByteBuddy/cglib for it.
- **`TimedLazy.get()`** re-checks under the lock, so concurrent expiry reloads once; `reload()` always reloads. Loading, `set` and `invalidate` share the lock, so a `set` during a load is applied after it and is not overwritten. TTL uses `System.nanoTime()` (elapsed time, immune to clock changes).
- **`Lazy.get()`** retries if the value it lost the CAS to was invalidated before it could be read (never returns `null`).
- **flatMap null guard.** Every `flatMap` (`FOption`, `Try`, `Result`, `Either`) rejects a `null` container from the mapper (`IllegalStateException`; `Try`/`Result` turn it into a failure). `Result.failure(null).toTry()` uses an `IllegalStateException` cause. `FOption.fstream()` throws on `next()` after `close()`, like `AbstractFStream`.

## Usage and API-change cost

To check callers in marmot/jarvey (they can't be built with gradle here), use javac over each root's sources with the gradle-resolved external classpath and diff against a pre-change error list; grep alone misses same-named methods on other types. Heavily used surface (approximate call sites outside utils.func): `Result` (~430), `FOption` (everywhere), `Nullables` (~150, all `Nullables.x(` qualified), `Unchecked.*` (~115), `Lazy.of` (~55), `Funcs.*` (~55 files), `MultipleCases` (~40), `Either` (~40, mostly marmot).
